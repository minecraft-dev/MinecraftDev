Reports added members not matching the correct name format

Members added by mixins share the target class with members added by every other mod. Prefixing their names with the mod id avoids conflicts between mods that add members with the same name. The required pattern and which members are reported can be configured. This should be done when @Unique can't be used. 


@Override public void doSomething() { ... }       // bad
@Override public void myMod$doSomething() { ... } // good

By default, methods implemented from interfaces in the current project are not reported in the following cases, each of which can be disabled:

  • A parameter or return type of the method is a class from the current project, making a conflicting descriptor very unlikely.
  • The interface is injected with transitive-inject-interface in a class tweaker file, meaning it is intended to be used by other mods.
  • The interface is in a package matching the configured API package pattern.
