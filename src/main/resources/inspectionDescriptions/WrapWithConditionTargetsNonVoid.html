Reports when @WrapWithCondition targets a non-void instruction followed by a pop

When the condition is false, @WrapWithCondition skips the call, so the call has no return value. This only works because the return value is discarded, and breaks if the target method is changed to use it, including by another Mixin. Use @WrapOperation instead, which can provide a return value. 


// target: list.add(item);

// bad
@WrapWithCondition(method = "foo", at = @At(value = "INVOKE", target = "Ljava/util/List;add(Ljava/lang/Object;)Z"))
private boolean shouldAdd(List<Item> list, Item item) {
    return item != null;
}

// good
@WrapOperation(method = "foo", at = @At(value = "INVOKE", target = "Ljava/util/List;add(Ljava/lang/Object;)Z"))
private boolean add(List<Item> list, Item item, Operation<Boolean> original) {
    return item != null && original.call(list, item);
}
