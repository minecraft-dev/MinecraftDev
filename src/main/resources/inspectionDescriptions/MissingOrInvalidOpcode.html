Reports missing or invalid usages of opcode

Some injection points, such as FIELD, match several kinds of instructions, and it's good to specify an opcode to say which kind to target. For example, without an opcode, FIELD matches both reads and writes of the field, which is rarely intended.

Other injection points ignore the opcode, so specifying one there is misleading. 


// bad
@At(value = "FIELD", target = "Lcom/example/Foo;bar:I")

// good
@At(value = "FIELD", target = "Lcom/example/Foo;bar:I", opcode = Opcodes.PUTFIELD)
